# Phenix authentication UX acceptance

This is a **user-run, installed Neovim** acceptance plan for the P1
OpenAI API-key and ChatGPT OAuth implementations. The default `nvim-nix`
editor includes both methods and is covered by deterministic CI, but a real external
OAuth account, model inference, refresh and remote sign-out have **not** been
independently accepted. API billing and ChatGPT subscription entitlements
remain distinct.

## 1. Real OpenAI API-key UX (requires your own key)

On the machine with your graphical Neovim/browser environment:

```sh
nix run 'github:matthis-k/phenix-nvim#nvim-nix'
```

The normal editor initializes its private local file-backed credential store
on first use; **no Nix or shell credential setup is needed**. This store is
**not encrypted at rest**. Never put an OpenAI API key in a Nix flake,
command-line argument, Git commit or ChatGPT conversation. Use Neovim's
masked key entry for one-time local storage, or choose an environment variable
name if you intentionally manage the variable separately.

Inside Neovim:

1. Run `:Phenix auth`, select the declared OpenAI API connection and direct
   API-key method. The admitted profile is `openai/api/personal`.
2. Enter a valid **OpenAI API billing** key via the masked prompt. Credential
   storage alone must not produce a successful login; Phenix must verify it
   with `https://api.openai.com/v1/models`.
3. Before opening any session, run `:Phenix model`. Choose a model actually
   offered by the authenticated account and confirm that the choice is saved
   as a **connection default**. The picker must not create a session.
4. Run `:Phenix new`. Confirm that this new Basic session adopted the exact
   selected model, then optionally use `:Phenix model` inside the session to
   verify session-scoped model overrides.
5. Type a short prompt in the compose buffer and send with Enter in normal
   mode. Expect a streamed assistant response from the selected HTTP Model.
   A discovered model may still be denied for quota/billing; this is a
   provider error, not proof of a broken authentication contract.
6. Quit and reopen the normal editor. The protected credential and session
   record should remain available without Nix rebuild or shell setup; auth status and
   model eligibility must be **reverified**, not assumed from the local file.
7. Run `:Phenix auth revoke openai api personal` and explicitly confirm.
   A subsequent selected-model request and a reload after restart must not
   reuse the revoked credential.

### Negative cases

- Enter an invalid key. It may be stored, but the provider status must be
  unavailable. The UI must not announce a verified account or select a
  native credentialed model based only on storage success.
- Try choosing an unadmitted profile. The launcher must refuse it without
  touching another account's credential resource.
- Start `nvim-nix-managed` instead. `:Phenix providers` may show
  registrations, but `:Phenix auth` must **not** collect a key or launch a
  browser: the catalog-only composition has no login grant.

## 2. Deterministic Neovim OAuth UX regression

```sh
nix build 'github:matthis-k/phenix-ai.nvim#checks.x86_64-linux.ui-fast'
```

The merged `p1_oauth_ux_journey.lua` test drives `:Phenix auth` using a
scoped runtime mock. It verifies browser challenge, pending/repeated/reissued
challenge, completed provider status, expiry, unsafe URL refusal, and that Lua
never acquires an OAuth access/refresh token. It makes no external login
request and does **not** establish ChatGPT plan entitlement.

## 3. ChatGPT browser OAuth: live-account acceptance outstanding

Use the released combined editor on a machine with a browser and an eligible
account. **Do not paste tokens or authorization codes into issues or chats.**

```sh
nix run 'github:matthis-k/phenix-nvim#nvim-nix'
```

The default launcher creates and validates a private 0700 directory under
`$XDG_STATE_HOME/phenix/p1-auth-credentials` (or
`~/.local/state/phenix/p1-auth-credentials`) automatically. No credential
environment variables or manual `mkdir` / `chmod` are required. The
credential backend is local and permission-protected, **not encrypted
at rest**. No ChatGPT entitlement is inferred simply because an OAuth
option is present.

1. Run `:Phenix auth` and select the OpenAI ChatGPT connection and its
   browser OAuth method. Follow the URL generated by the native provider.
   Cancel once using Esc/q and verify no authenticated profile appears.
2. Repeat the sign-in, finish the browser consent/callback, and verify that
   the **same explicitly admitted** `openai/chatgpt/personal` profile is
   reported as authenticated. Reject mismatched callbacks, expired attempts,
   or unrecognized scopes; Lua must never receive access/refresh tokens.
3. **Before `:Phenix new`**, run `:Phenix model`. Confirm that the menu lists
   the verified account's actual model IDs, not `phenix.model.http` as a
   substitute for a model. Select one, then run `:Phenix new` and verify the
   session adopts it. Submit a prompt and confirm a real streamed response.
   Account, discovery or quota denial must be reported with an actionable
   reason instead of offering a fallback model.
4. Restart Neovim with the same private directory. The account must remain
   protected, and model eligibility must be rechecked. Exercise an expired
   access token to validate provider-owned refresh, rather than assuming
   presence in storage is enough.
5. Run `:Phenix auth revoke openai chatgpt personal`, explicitly confirm,
   and verify that subsequent model requests and restart cannot reuse the
   local OAuth account. Observe the issuer response independently if
   possible; only a confirmed remote response establishes remote sign-out.
6. Repeat sign-out with the issuer network deliberately unavailable. The
   client must warn that the credentials were removed **locally**, but
   remote revocation is **unconfirmed**. It must not display any raw provider
   error payload or falsely report server-side sign-out.

### Automated, credential-free release gate

```sh
nix build 'github:matthis-k/phenix-nvim#checks.x86_64-linux.p1-combined-auth-frontend-wiring'
```

The distribution CI also launches the normal `nvim-nix` headlessly, opens
the real `:Phenix auth` provider picker with no credential environment,
and retains separate combined-auth and local streaming-provider fixtures. These verify package wiring and native
ACP behavior, **not** authorization from the external ChatGPT issuer.
